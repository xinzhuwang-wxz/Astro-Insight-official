# 第二站首个子模块：高维数据降维可视化详细计划

## 1. 这一页的目标

这一页的核心目标不是“把所有高维算法都堆上去”，而是让用户能快速回答这几个问题：

1. Gaia/HSC 数据里有哪些潜在结构？
2. 不同算法看到的结构是否一致？
3. 某个点/簇对应的原始天体参数是什么？
4. 是否存在异常点、离群源、特殊候选体？
5. 用户能否在网页上通过切换算法、筛选字段、刷选区域来探索数据？

所以这部分建议做成一个“**降维探索台**”，而不是单纯一张散点图。

## 3. 这一模块的功能拆分

建议把“高维数据降维可视化”拆成 4 个子功能区：

### A. 数据概览区
用于告诉用户当前加载的是哪批数据，以及数据质量如何。

展示内容建议包括：

- 样本总数
- 清洗后保留数
- 缺失值比例
- 异常值剔除数量
- 可用特征数
- 当前采用的特征集类型

### B. 降维主视图区
这是页面核心。

支持切换：

- PCA
- t-SNE
- UMAP

显示方式支持：

- 2D 散点
- 3D 散点

编码方式建议：

- 颜色：有效温度 `teff` 或类别标签
- 点大小：星等 `phot_g_mean_mag`
- 点透明度：密度或置信度
- 悬停提示：完整天体参数

### C. 聚类与异常区
用于辅助解释高维结构。

显示：

- DBSCAN 聚类结果
- 离群点高亮
- 聚类统计卡片
- 单簇参数概览

### D. 原始数据详情联动区
当用户点击某个点或刷选某个簇后，右侧显示：

- Gaia/HSC 原始字段
- 对应行记录摘要
- 是否缺失关键字段
- 是否属于异常源
- 可能的物理解释标签

## 4. 数据流与处理流程

这里建议直接复用项目里的现有数据处理模块，不要在前端重复做重活。

### 4.1 数据来源
文档里已经明确了主要来源：

- `clean_cols_GaiaDR3Crab.xlsx`

可以进一步按需求扩展：

- 若后续要联合 HSC，可再接入 `clean_cols_HSCv3.1Crab.xlsx`
- 如果需要更适配可视化，建议先在后端生成统一的“分析视图表”

### 4.2 预处理流程
建议标准流程如下：

1. 读取原始表格
2. 选择高维特征列
3. 缺失值处理
4. 异常值剔除
5. 特征标准化
6. 降维
7. 聚类
8. 输出前端可直接消费的结果 JSON

### 4.3 特征选择建议
第一版不要选太多，建议先用一组稳定且有物理意义的特征。

#### 基础特征
- `ra`
- `dec`
- `parallax`
- `parallax_error`
- `pmra`
- `pmdec`
- `phot_g_mean_mag`
- `bp_rp`
- `bp_g`
- `g_rp`
- `teff_gspphot`
- `mh_gspphot`
- `ruwe`

#### 派生特征
- 自行总量：`sqrt(pmra^2 + pmdec^2)`
- 绝对星等：`M_G`
- 颜色指数组合
- 视差置信度比值
- 运动异常指标

### 4.4 清洗规则
文档里提到的规则可以细化为：

- 剔除 `parallax_error > 3σ`
- 剔除视差为负且无法解释的样本
- 剔除关键字段缺失过多的记录
- 对极端值进行 winsorize 或稳健缩放
- 对重复源做去重

### 4.5 标准化方式
建议默认使用：

- `StandardScaler`

如果后续发现极端离群值太多，可以切换为：

- `RobustScaler`

## 5. 降维算法的实现策略

### 5.1 第一版支持的算法
建议第一阶段支持三种：

1. **PCA**
   - 适合解释性最强
   - 用来展示方差贡献和主成分结构
   - 适合做默认首屏

2. **t-SNE**
   - 适合看局部簇结构
   - 适合探索相似天体聚集

3. **UMAP**
   - 适合兼顾局部和全局结构
   - 性能通常比 t-SNE 更适合网页交互

### 5.2 算法切换原则
建议前端切换算法时不直接在浏览器本地算，而是：

- 前端发请求
- 后端返回对应降维结果
- 前端重绘图层

这样后续样本量大时更稳。

### 5.3 PCA 的特殊输出
PCA 不只是一个散点图，还应该额外输出：

- 各主成分解释方差比
- 累积解释方差曲线
- 主成分载荷排行

这样它才真正有“分析价值”。

### 5.4 t-SNE / UMAP 的特殊输出
这两类重点提供：

- 簇结构
- 离群点
- 局部邻域关系

可额外记录参数：

- `perplexity`
- `n_neighbors`
- `min_dist`

让用户在右侧面板调整。

## 6. 聚类与异常检测计划

### 6.1 聚类目标
聚类不是为了“硬分组”，而是为了辅助理解降维后的结构。

建议使用：

- `DBSCAN`：适合发现密度簇和噪声点
- 可选 `KMeans`：用于对比展示

### 6.2 异常点定义
异常点可以来自：

- DBSCAN 中的噪声点
- 特征空间中 Isolation Forest 判定的异常
- 物理参数极端偏离的样本

### 6.3 可视化方式
异常点建议：

- 用红色描边
- 放大一点
- 悬停时显示“异常原因标签”

比如：

- 高 `ruwe`
- 视差误差过大
- 运动速度异常
- 颜色与温度不一致

## 7. 前端交互设计

### 7.1 页面布局建议
建议布局为三栏：

#### 左栏：控制面板
- 数据集选择
- 算法选择
- 特征选择
- 参数调节
- 聚类开关
- 异常点开关

#### 中栏：可视化主图
- 2D/3D 降维图
- 支持缩放、拖拽、框选、悬停
- 支持图层切换

#### 右栏：详情面板
- 当前选中点详情
- 当前选中簇统计
- 原始参数表
- 导出按钮

### 7.2 交互动作
建议至少做这些：

- 单击点：查看单源详情
- 框选区域：显示该区域统计
- 算法切换：重新渲染
- 特征切换：重新降维
- 聚类开关：叠加/隐藏聚类边界
- 异常点开关：只看离群点
- 重置按钮：回到默认视图

### 7.3 联动逻辑
建议联动链路是：

- 选中点 → 右栏显示详细参数
- 选中簇 → 右栏显示簇统计
- 刷选区域 → 更新统计卡片和高亮列表
- 改算法 → 保留筛选条件并重新计算

## 8. 数据接口设计建议

为了后续好扩展，建议后端提供以下接口：

### 8.1 数据概览接口
返回：

- 总样本数
- 清洗后样本数
- 缺失值统计
- 特征列表
- 当前版本信息

### 8.2 降维计算接口
请求参数：

- 算法类型
- 特征列表
- 过滤条件
- 降维参数
- 是否聚类

返回：

- 降维坐标
- 点元信息
- 聚类标签
- 异常标签
- 统计摘要

### 8.3 单点详情接口
输入：

- source id 或 row id

输出：

- 原始字段
- 派生字段
- 所属簇
- 是否异常
- 关联物理解释

### 8.4 区域统计接口
输入：

- 选区范围
- 算法名
- 筛选条件

输出：

- 选中点数
- 平均星等
- 平均温度
- 平均视差
- 聚类分布

## 11. 性能与工程约束

### 11.1 性能问题预判
高维降维最大的问题通常不是算法，而是：

- 样本太多
- 切换算法导致重新计算慢
- 前端点太多渲染卡
- 3D 图交互不稳定

### 11.2 解决策略
建议：

- 后端缓存降维结果
- 对超大数据做采样预览
- 选区后再请求全量明细
- 2D 默认优先于 3D
- t-SNE 默认小样本，UMAP 适合更大数据

### 11.3 结果缓存键
缓存时建议按这些维度区分：

- 数据版本
- 算法类型
- 特征集合
- 过滤条件
- 参数组合
